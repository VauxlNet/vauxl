# ADR-005: Session Ratchet — Megolm Rotation with HKDF-Derived VSX Key Schedule

**Status:** Accepted
**Date:** 2026-01-01

## Context

Matrix uses Megolm for group session encryption, with periodic session
rotation to limit cryptographic exposure. The VSX extension layer requires
additional key derivation to support post-quantum forward secrecy without
modifying the base Megolm ratchet.

## Decision

Use vodozemac's built-in Megolm session rotation as the standard E2EE
mechanism. For the VSX extension layer, derive an additional per-message key
schedule using HKDF (SHA-512) from the Megolm session key at rotation time.
This derived schedule is consumed by the VSX double-ratchet extension and is
transparent to standard Matrix clients.

## Consequences

- Positive: standard Matrix E2EE remains unmodified and compatible.
- Positive: VSX extension keys are cryptographically separated from Megolm
  session keys.
- Positive: HKDF is well-studied, with safe Rust bindings.
- Negative: VSX extension adds per-message overhead for clients that opt in.
- Negative: key schedule must be specified in a separate VSX extension
  document — not part of the core server implementation.

## Alternatives Considered

- **Forking Megolm**: would break spec compliance.
- **Re-encrypting at the application layer**: redundant encryption passes.
