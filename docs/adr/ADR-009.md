# ADR-009: Client Model — Headless Rust Core with ZeroMQ IPC

**Status:** Accepted
**Date:** 2026-01-01

## Context

The client needs a shared core for Matrix operations, crypto, and state
management, while supporting multiple frontends (Electron/Tauri, web, CLI).
Duplicating core logic per frontend is unsustainable.

## Decision

Implement the client as a headless Rust core process that communicates with
frontends via ZeroMQ (ZMQ) IPC. The core owns all Matrix state, crypto
operations, and database access. Frontends are swappable UI layers that
communicate over a documented ZMQ message schema.

## Consequences

- Positive: one core implementation serves all frontends.
- Positive: frontends can be written in any language with ZMQ bindings.
- Positive: core can be tested headlessly without a UI.
- Negative: IPC introduces latency vs direct in-process calls.
- Negative: ZMQ message schema must be versioned and documented.
- Negative: debugging across process boundaries is harder.

## Alternatives Considered

- **In-process library**: tightly couples frontend to Rust, limits frontend
  language choice.
- **HTTP localhost API**: higher overhead, no pub/sub pattern built in.
