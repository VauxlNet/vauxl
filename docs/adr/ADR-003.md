# ADR-003: Baseline E2EE — Olm and Megolm via vodozemac

**Status:** Accepted
**Date:** 2026-01-01

## Context

Matrix mandates end-to-end encryption for private messaging using the Olm
(double ratchet) and Megolm (group ratchet) algorithms. Vauxl must implement
this baseline to be Matrix-compliant.

## Decision

Use the `vodozemac` Rust crate for all Olm and Megolm cryptographic
operations. Vodozemac is the reference Rust implementation maintained by the
Matrix.org Foundation, is audited, and exposes a safe public API.

## Consequences

- Positive: audited, maintained implementation trusted by the Matrix ecosystem.
- Positive: safe Rust API reduces risk of misuse in application code.
- Positive: aligns with ruma's expected crypto primitives.
- Negative: vodozemac releases occasionally lag behind spec changes.
- Negative: only covers standard Matrix E2EE — VSX extensions (post-quantum)
  require additional primitives in the crypto crate.

## Alternatives Considered

- **libolm (C)**: FFI overhead, C memory safety risks.
- **Custom implementation**: unacceptable audit burden for a spec-mandated
  baseline.
