# ADR-001: Primary Protocol — Matrix Client-Server and Server-Server API

**Status:** Accepted
**Date:** 2026-01-01

## Context

Vauxl needs a communication protocol. Building a custom protocol from scratch
would increase audit surface, delay interoperability, and fragment the
federated ecosystem.

## Decision

Adopt the [Matrix protocol](https://spec.matrix.org) as the primary
communication protocol, implementing both the Client-Server (CS) and
Server-Server (SS / Federation) API via the `ruma` Rust crate. The ruma crate
provides type-safe event models, endpoint definitions, and serialisation
aligned with the Matrix spec.

## Consequences

- Positive: immediate compatibility with the existing Matrix federation
  ecosystem (bridges, clients, other homeservers).
- Positive: ruma keeps Vauxl's API surface spec-compliant without hand-rolling
  models.
- Negative: protocol evolution is constrained by the Matrix spec — Vauxl
  extensions must be additive.
- Negative: ruma development pace may lag the Matrix spec.

## Alternatives Considered

- **Custom protocol**: full control but no federation out of the box.
- **IRC/SMTP**: insufficient for modern E2EE and state management.
