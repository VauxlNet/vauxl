# ADR-007: Password Fallback — Argon2id

**Status:** Accepted
**Date:** 2026-01-01

## Context

Not all clients or environments support WebAuthn (e.g., headless bots, legacy
clients, CLI tools). A password-based fallback is necessary for
interoperability, but it must be implemented with current best-practice
hashing.

## Decision

Use Argon2id (the winner of the Password Hashing Competition) as the sole
password hashing algorithm. Use the `argon2` Rust crate with the
recommended parameters: 64 MiB memory, 3 iterations, 4 parallelism. Salts are
generated using a CSPRNG (OsRng). Password-based login is rate-limited and
logged; it can be disabled by server administrators who require WebAuthn-only
access.

## Consequences

- Positive: Argon2id is resistant to GPU and ASIC brute-force attacks.
- Positive: the `argon2` crate is pure Rust, no C dependencies.
- Positive: server operators can disable password auth entirely if desired.
- Negative: Argon2id is memory-intensive — poor fit for low-resource
  environments (mitigated: adjustable parameters).
- Negative: passwords are still phishable — WebAuthn should always be the
  preferred path.

## Alternatives Considered

- **bcrypt**: older, lower memory hardness.
- **scrypt**: acceptable but less broadly adopted than Argon2id.
